# Rails and React harness V2.5.1.1.0

V2.5.1.1.0 is a candidate base revision built on V2.4.1.1.0. It moves consequential workflow checks into implementation and keeps the performance and AI repair-loop capabilities. The packaged assignment, screenshots, spec, and original launch file are byte-identical to the baseline. The standalone launch text is shared across the baseline and candidate.

## Research applied

- OpenAI's harness engineering write-up describes checking invariants mechanically while allowing implementation choices. I applied that to packaged-input verification and executable checks on persistence and data work. The instruction to trace a workflow leaves class and method structure open. Anthropic's long-running-agent work emphasizes incremental verification and externally observable state, which informed checking a slice before extending it. [OpenAI harness engineering](https://openai.com/index/harness-engineering/#enforcing-architecture-and-taste), [Anthropic long-running harnesses](https://www.anthropic.com/research/effective-harnesses-for-long-running-agents)
- Anthropic's evaluation guidance distinguishes model judgments from checks against observable outcomes. This informed independent source review for readability and verified state and measurements for behavior. The same criteria and separate pre-grade and final revisions make late repairs visible. One pair is evidence about those runs. [Anthropic agent evaluations](https://www.anthropic.com/research/demystifying-evals-for-ai-agents)
- The previous builds lock Rails and Active Record 8.1.4.1. The Rails 8.1 query guide covers scoped queries, association loading, and query plans. Active Support provides SQL and instantiation events, which support counting work in the caller. Stack Overflow's association-loading discussion illustrates how adding a new relation inside a loop can still issue more queries. The probe counts Rails instantiations and ordinary direct SQL writes on one thread. Database scans, asynchronous work, and lock duration require separate evidence. [Rails 8.1 Query Interface](https://guides.rubyonrails.org/v8.1/active_record_querying.html), [Rails 8.1 Instrumentation](https://guides.rubyonrails.org/v8.1/active_support_instrumentation.html#active-record), [Stack Overflow association loading](https://stackoverflow.com/questions/65678429/rails-n-1-query-problem-when-fetching-associated-records-with-where-condition)
- The Rails transaction API ties atomicity to the participating connection and explains rollback and nested transactions. A failed operation should be checked through persisted state and its caller. Rails autoloads custom directories under `app`, and the Rails forum and Stack Overflow discussions show the tradeoffs of organizing service objects. The harness evaluates rule ownership and a visible sequence. [Rails 8.1 Transactions API](https://api.rubyonrails.org/v8.1/classes/ActiveRecord/Transactions/ClassMethods.html), [Rails 8.1 Autoloading](https://guides.rubyonrails.org/v8.1/autoloading_and_reloading_constants.html), [Rails forum service objects](https://discuss.rubyonrails.org/t/service-objects-support-in-core-rails/74556), [Stack Overflow service objects](https://stackoverflow.com/questions/52526322/what-do-folks-use-app-services-in-rails-applications)

## Package verification

- Fresh extraction verified all 53 expected inputs and ten screenshot signatures. Scratch mutations failed with a tampered guide, missing manifest, empty manifest, omitted entry, duplicate entry, or outside path. Restoring the inputs returned a pass. Twenty common assignment, spec, reference, and launch files matched byte for byte.
- The probe ran against real Active Record 8.1.4.1 using synthetic SQLite data. With one relevant row, all three paths returned the same business result in one database statement. Instantiated records were 1 on the control, 1 on a scoped query after adding 50 unrelated records, and 51 on the unscoped query. Additional checks observed one versus four direct writes, distinguished an actual query from a cache hit, and verified that exceptions leave no temporary SQL subscription. These results validate the instrument on those cases.

## Scope and status

The full-app trials were stopped after the scope was clarified. The results here cover the harness package and its focused checks. Whether this revision produces a more readable, easier-to-change, or faster application remains unverified.
