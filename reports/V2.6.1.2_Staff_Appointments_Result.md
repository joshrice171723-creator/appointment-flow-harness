# V2.6.1.2 staff appointments refactor

**Grade: REVISE.** The controller is organized in request order with named private steps. The endpoint still uses a PostgreSQL expression to match open reviews to visits. The strict plain Active Record rule requires a further change to that relationship.

The trial started from frozen V2.6 commit `b30516d41f740154aa13b5d0f7791fc9580486ba`. Both versions passed the authenticated checks for all four filters, order, totals, review flags, clinic isolation, a 200-row response cap, and error responses. A disposable rule change lowered the cap to 199 and verified the expected behavior.

| Confirmed tab on the grown fixture | SQL reads | Rows returned to Rails |
|---|---:|---:|
| Frozen V2.6 | 8 | 10 |
| V2.6.1.2 refactor | 13 | 13 |
| Additional plain Active Record review lookup trial | 14 | 514 |

The fixture added 500 out-of-day reviews and 500 extra appointment times in the same week. Six per-day counts replaced the original grouped weekly count, using the selected day's existing total for the seventh day. The alternative review lookup transferred the unrelated candidate IDs to Rails. Local timings varied enough that these checks establish the work each version did and leave the latency difference unresolved.

The structural change passed the same checks with the original query shape in an earlier checkpoint. The measured improvement in readability can be reviewed independently of the query changes. Retaining database-side review filtering with plain Active Record would require a normalized, backfilled message-to-visit relationship outside the controller-only trial.
