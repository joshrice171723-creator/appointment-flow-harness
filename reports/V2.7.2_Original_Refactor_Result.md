# V2.7.2.1.0 original app refactor

**Instruction isolation was incomplete in this first trial.** The copy retained the original coding guides, rubric, and review history. The agent's recorded searches exposed old guide and review excerpts, including from neighboring copies. The measurements below describe the resulting code. Attribution to the V2.7.2.1.0 harness alone is inconclusive. A second trial starts from the same original commit with those materials excluded before creating its Git history.

This trial ran on a disposable copy of the original `appointment-flow` at `db037d7`. It changed the staff appointments action and the query it calls, keeping the HTTP contract and schema in scope as constraints. GPT‑6.1 Sol High ran for about 23 minutes with optional skills, hooks, plugins, and memory disabled.

**Grade · REVISE.** The final comparison matched all ten frozen endpoint responses and twelve focused responses. The focused cases covered authorization, dates and DST, visible history and replies, opt-outs, and three controlled concurrent writes. The backend suite passed 118 tests and 1,797 assertions. The independently repeated ten-request comparison passed on the final working copy.

| Same request and response | SQL statements | Rows returned to Rails | Model objects instantiated |
|---|---:|---:|---:|
| Dated request with 24 appointments | 12 → 12 | 124 → 100 | 147 → 75 |
| Dated request after 600 retired revisions and 1,200 events were added | 12 → 16 | 1,852 → 41 | 1,854 → 29 |
| Undated request after 300 past visits were added | 8 → 9 | 314 → 322 | 312 → 11 |
| Undated request returning 184 appointments | 8 → 9 | 188 → 372 | 187 → 187 |

The dated view avoids building Ruby model objects for old visit revisions and events it never displays. The undated view reads a narrow set first to avoid building objects for hidden visits. It then reads the visible visits again. With 184 visible visits, it transfers more rows and builds the same number of model objects. The extra read can also pick up a confirmation that committed after the first read. The endpoint has no documented point-in-time snapshot guarantee.

The review kept REVISE because the existing shared freshness check still uses SQL to read PostgreSQL's clock and the reply lookup still scans event history in PostgreSQL. Improving those paths requires changing the shared freshness code or the database schema, outside this trial. Rows returned measure work transferred to Rails. They do not measure how many rows the database scanned or establish production latency.
