# V2.9.5.1.1 matched full-app benchmark

**44 of 44 checks passed** on `e26f412b52c435e031e5beb40f33cbfddf652f59`. The standard database-work score is **68/100**. Automation coverage is **83/100** for this measured scope. The highest standard score is V2.7.4 Active Record rewrite at 94/100.

## What the benchmark exercises

The suite covers first reminder batches, appointment pages, incoming confirming replies, unchanged retries, later-day visibility, and unique or shared contact ownership. It includes 44 recorded outcomes across 14 fixture scenarios. It uses the same four case files, shared fixture, tracer, caller runner, and summarizer as the V2.8.5 comparison. Their recorded hashes match.

The adapter maps the rebuilt app to `ReminderBatch#run`, `GET /api/staff/appointments`, and `POST /api/demo/clinics/:clinic_id/patients/:patient_id/replies`. It follows appointment paging. Staff sign-in is outside the measured request. It reads persisted decisions and reviews to check the result. The database role is `apex_app`. The replica's owner connection sets up fictional test records outside the measured operations.

The database was private to this run. The source was a Git archive of the frozen build. The application and existing harness package received no edits. The schema came from the build's own migration and PMS setup files. The Active Record source check ran against that migrated database and passed.

## Evidence and limits

- End-to-end benchmark time was 227.8 seconds. That includes source extraction, private database setup, migrations, measurements, source validation, and teardown.
- The 1–100 performance score weights returned rows, affected rows, write statements, total statements, and model instances. The score compares matching recorded outcomes. Timing is available in the raw data and has one sample per operation.
- The suite measures the named operations. Patient history, staff follow-up writes, and leadership reports have separate saved checks. This replay does not give those paths a new performance result.
- The standard benchmark captured statements and row counters. Earlier targeted HTTP checks captured plans. A query plan comparison was not repeated in this 44-case run.
